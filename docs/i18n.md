# Multi-language (i18n)

## 1. Mục tiêu

Chuẩn hoá response message theo ngôn ngữ client (EN/VI) dựa trên header hoặc query param.

## 2. Cơ chế chọn ngôn ngữ

Server ưu tiên theo thứ tự:

1. Query param `lang` (ví dụ `?lang=vi`)
2. Header `X-Lang` (ví dụ `X-Lang: vi`)
3. Header `Accept-Language` (ví dụ `Accept-Language: vi-VN,vi;q=0.9,en;q=0.8`)

Ngôn ngữ hiện hỗ trợ: `en`, `vi`, `th`, `zh`, `id`. Mặc định: `en`.

Server set thêm response header: `Content-Language: <lang>`.

## 3. Response được dịch

Các field được dịch theo catalog:

- `message`
- `error` (chỉ dịch khi payload là `string`, `[]string`, hoặc `[]interface{}` chứa string)

Các message dạng tự do không nằm trong catalog sẽ giữ nguyên.

## 4. File ngôn ngữ

Mặc định server load file JSON tại:

- `resources/i18n/<lang>/*.json` (khuyến nghị)

Ví dụ:

- `resources/i18n/en/common.json`
- `resources/i18n/en/auth.json`
- `resources/i18n/en/product.json`

Có thể override thư mục bằng env:

- `I18N_DIR=/path/to/i18n`

## 5. Quy ước key

Key theo domain:

- `common.*`: message chung cho toàn hệ thống
- `auth.*`: message cho domain auth
- `product.*`: message cho domain product

Ví dụ:

- `common.internal_server_error`
- `auth.unauthorized`
- `product.not_found`

## 6. Thêm key / ngôn ngữ mới

File mapping & loader: [i18n.go](file:///Users/thaidong/Projects/study/go-crud/internal/application/i18n/i18n.go)

Quy trình:

1. Thêm key vào các file `resources/i18n/<lang>/*.json` (đúng domain).
2. Đảm bảo code luôn trả message dưới dạng key (ví dụ `common.not_found`) thay vì text tự do.

Ví dụ: thêm key `auth.user_not_found`:

- `resources/i18n/en/auth.json`: `"auth.user_not_found": "User not found"`
- `resources/i18n/vi/auth.json`: `"auth.user_not_found": "Không tìm thấy người dùng"`
